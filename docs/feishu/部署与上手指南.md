# Pocket Earth × 飞书：部署与上手指南

## 它解决什么问题

团队从游记、研究报告、课程材料和现场照片中整理地点时，常见问题不是“AI 不会总结”，
而是结果缺少页码证据、无法协作审核、无法继续进入文档或表格流程。Pocket Earth 飞书版
把这个过程做成一条可审计的协作工作流。

飞书不是结果展示壳：飞书身份创建任务，文件触发真实 OCR 与 Qwen，用户在飞书里决定
哪些地点可以写回，最终文档、多维表格和消息卡片仍在飞书内继续协作。

## 核心流程

1. 用户从飞书工作台打开 `/feishu`，JSSDK `requestAccess` 获取临时授权码。
2. 服务端用授权码换取用户身份；用户 access token 只保存于服务端短时会话。
3. 用户上传 PDF、PNG、JPG/JPEG 或 WebP。服务端以租户、文件 SHA-256 与工作流版本幂等建任务。
4. PaddleOCR / PP-Structure 返回逐页文字、页码和置信度。
5. Qwen 只从 OCR 内容抽取地点；每条 `evidence` 必须能在对应页原文中找到，否则整次推理失败。
6. 用户在飞书内审核地点、原文证据和坐标。模型不确定的坐标保持为空，禁止猜测。
7. 确认后生成飞书文档，可选写入多维表格，并向用户发送消息卡片。

状态机为：

`queued → ocr_running → qwen_running → awaiting_review → writing_back → completed / failed`

## 飞书应用配置

1. 在飞书开放平台创建“企业自建应用”，启用网页应用和机器人能力。
2. 网页应用主页设置为 `https://你的域名/feishu`。生产环境必须使用飞书可访问的公网 HTTPS。
3. 按实际能力申请最小权限：网页免登、获取用户基本信息、创建/编辑文档、发送消息；使用多维表格时再增加表格记录写权限。
4. 事件回调地址设置为 `https://你的域名/api/feishu/events`，在服务端配置 Verification Token；使用 Encrypt Key 时服务端还会校验 `X-Lark-Signature` 和时间窗。
5. 把 `.env.example` 复制为 `.env`，填写 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、回调安全参数和 `FEISHU_WEB_BASE_URL`。

密钥没有 `VITE_` 前缀，不会进入浏览器包。生产环境必须保持：

```dotenv
FEISHU_DEV_BYPASS_AUTH=false
FEISHU_ALLOW_PREEXTRACTED_OCR=false
```

## OCR 服务契约

`PADDLE_OCR_URL` 必须指向真实的 PaddleOCR / PP-Structure 服务。Pocket Earth 发送：

```json
{
  "fileName": "材料.pdf",
  "mimeType": "application/pdf",
  "dataBase64": "JVBERi0xLjQ...",
  "features": ["ocr", "layout", "page_number", "confidence"]
}
```

OCR 服务返回：

```json
{
  "engine": "paddleocr-pp-structure-v3",
  "pages": [
    { "page": 1, "text": "这一页识别出的完整文字……", "confidence": 0.96 }
  ]
}
```

空文本、HTTP 错误或缺少 `pages` 会把任务标为 `failed`，不会回退为硬编码地点。

## 运行与验证

```bash
npm ci
npm run typecheck
npm test -- --run
npm run build
node server.mjs
```

本地 UI 验收可暂时设置 `FEISHU_DEV_BYPASS_AUTH=true`，然后打开
`http://localhost:3009/feishu`。此开关只绕过本地免登，不会伪造 OCR、Qwen 或飞书写回。

正式验收至少覆盖：飞书桌面端与移动端、10 页 PDF、同文件重复提交、OCR/Qwen 失败重试、
Qwen 空响应和非 JSON、页码证据核验、同一 taskId 贯穿全链路、浏览器产物中不存在 App Secret。

## API

- `GET /api/feishu/config`：浏览器可见的非敏感配置与能力状态。
- `POST /api/feishu/auth`：飞书授权码换服务端会话。
- `POST /api/feishu/events`：校验回调后快速 ACK，耗时任务异步执行。
- `POST /api/feishu/tasks`：上传文件并幂等创建任务。
- `GET /api/feishu/tasks/:taskId`：查询进度和结果。
- `POST /api/feishu/tasks/:taskId/retry`：失败后重试。
- `POST /api/feishu/writeback`：提交人工审核结果并写回飞书。

## 当前外部依赖

代码、测试和浏览器工作台已经落地。真正完成线上闭环仍需要参赛者自己的飞书应用凭据、
可访问的 PaddleOCR 服务、DashScope Qwen Key、公网 HTTPS 域名，以及可选的多维表格 token。
这些外部凭据不应提交到 Git。
