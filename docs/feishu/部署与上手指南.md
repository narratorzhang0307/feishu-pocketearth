# Pocket Earth × 飞书：部署与上手指南

## 它解决什么问题

团队从飞书游记、研究报告、课程材料和现场照片中整理地点时，常见问题不是“AI 不会总结”，
而是结果缺少页码证据、无法协作审核、无法继续进入文档或表格流程。Pocket Earth 飞书版
把这个过程做成一条可审计的协作工作流。

飞书不是结果展示壳：飞书身份读取用户有权访问的文档，Frost 将任务路由到原有
Book-to-Earth Skill，Qwen 根据文档原文生成空间知识，
用户在原 Pocket Earth 地球界面中确认哪些地点可以落地，结果再写回源文档和多维表格。

## 核心流程

1. 用户从飞书工作台打开 `/feishu`。页面仍是原 Pocket Earth，只在地球顶部增加一个小型“飞书”入口。
2. JSSDK `tt.requestAuthCode` 获取临时授权码，服务端换取飞书用户身份；用户 access token 只保存于服务端短时会话。
3. 用户在地球页打开醒目的飞书入口，粘贴自己有权限访问的新版飞书文档 `docx` 链接，直接点击“读取飞书原文并生成知识地球”。服务端以该用户身份读取文档纯文本，不接受任意外部 URL。
4. Frost 把任务交给已登记的 `pocket.book-to-earth` Skill；该 Skill 以 `pocket.mapping/v1` 为产物协议，Qwen 只从飞书文档原文抽取地点；每条 `evidence` 必须能在原文中找到，否则整次推理失败。
5. 待确认地点直接显示在原 Pocket Earth 内嵌面板中。模型不确定的坐标保持为空，禁止猜测。
6. 用户确认后，带有效坐标的地点进入原地球落点总线，并保留 Frost、Skill 和产物协议的审计信息；书籍、电影、照片等原子 Agent 不改逻辑。
7. 审核结果追加回源飞书文档；配置多维表格后同步写入记录，并可发送消息卡片。

PDF / PNG / JPG / WebP 上传与 PaddleOCR 是可选补充入口：

1. 用户上传真实文件，服务端按租户、文件 SHA-256 与工作流版本幂等建任务。
2. PaddleOCR / PP-Structure 返回逐页文字、页码和置信度。
3. 后续进入与飞书文档相同的 Qwen → 人工确认 → 地球 → 飞书写回流程。

状态机为：

`queued → ocr_running → qwen_running → awaiting_review → writing_back → completed / failed`

飞书地球面板已经接入原工程的 Frost Router，并只暴露比赛内置的 10 个 Skill。Frost 会生成可见计划，
再通过 `pocket-frost-task/v1` 把任务交给原 Skill 页面：书籍、电影、音乐、多视角等文本能力预填任务；
旅行预填约束；看展、阅读摘录、碑拓等视觉能力要求用户在原页面主动补图；未装备的模型能力进入 Skills Plaza。

其中 `pocket.book-to-earth` 额外完成了飞书 `docx` 的服务端直读、证据抽取、人工确址、地球落点和飞书写回适配。
其余 Skill 虽已完成“飞书/Frost → 原 Skill”的真实路由与任务交接，但尚未冒充拥有统一的文档直读或写回 Schema；
以后只有在各自声明输入、审核字段和写回契约后，才会登记为飞书文档直连适配器。

## 飞书应用配置

1. 在飞书开放平台创建“企业自建应用”，启用网页应用和机器人能力。
2. 网页应用主页设置为 `https://你的域名/feishu`。生产环境必须使用飞书可访问的公网 HTTPS。
3. 按实际能力申请最小权限：网页免登、获取用户基本信息、读取与编辑新版文档、发送消息；使用多维表格时再增加表格记录写权限。用户还必须本身有权访问所粘贴的文档。
4. 事件回调地址设置为 `https://你的域名/api/feishu/events`，在服务端配置 Verification Token；推荐同时启用 Encrypt Key。服务端会按飞书协议校验 `X-Lark-Signature` 与时间窗，AES-256-CBC 解密事件，再校验解密后的 Token。加密 URL challenge 可直接完成验证。
5. 把 `.env.example` 复制为 `.env`，填写 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、回调安全参数和 `FEISHU_WEB_BASE_URL`。

密钥没有 `VITE_` 前缀，不会进入浏览器包。生产环境必须保持：

```dotenv
FEISHU_DEV_BYPASS_AUTH=false
FEISHU_ALLOW_PREEXTRACTED_OCR=false
```

## 可选：自托管 OCR 服务

飞书文档主流程不依赖 OCR。若还要处理 PDF 和图片，仓库已提供 `services/paddle-ocr`，使用 PaddleOCR 3.7 的 `PPStructureV3.predict()` 处理
PDF 和图片，不会把文档发送给第三方 OCR SaaS。

```bash
docker build -t pocket-earth-paddle-ocr services/paddle-ocr
docker run --rm -p 8010:8010 \
  -e OCR_API_KEY=请替换为长随机值 \
  -e OCR_DEVICE=cpu \
  pocket-earth-paddle-ocr
```

然后设置 `PADDLE_OCR_URL=http://127.0.0.1:8010/v1/ocr` 和相同的
`PADDLE_OCR_API_KEY`。首次请求需要下载、加载官方模型，冷启动会比后续请求慢。

主服务向 OCR sidecar 发送：

```json
{
  "fileName": "材料.pdf",
  "mimeType": "application/pdf",
  "dataBase64": "JVBERi0xLjQ...",
  "features": ["ocr", "layout", "page_number", "confidence"]
}
```

OCR 服务返回：

```json
{
  "engine": "paddleocr-pp-structure-v3",
  "pages": [
    { "page": 1, "text": "这一页识别出的完整文字……", "confidence": 0.96 }
  ]
}
```

空文本、HTTP 错误或缺少 `pages` 会把任务标为 `failed`，不会回退为硬编码地点。

## 任务持久化与恢复

- 任务元数据、审核结果和写回检查点保存到 `var/feishu/tasks/`，服务重启后仍可查询。
- 飞书文档原文、原始文件 Base64 和飞书用户 access token 只保留在内存，不写入任务快照。
- OCR/Qwen 阶段被重启中断时，界面会要求重新上传同一文件，并以原 SHA-256 恢复同一 taskId。
- 写回阶段按“文档创建 → 文档块 → 多维表格 → 消息卡片”保存检查点；失败重试不会重复运行 OCR/Qwen。
- `var/feishu/` 已加入 `.gitignore`，审计和任务数据不会被提交到源码仓库。

### 上线前强制预检

填写 `.env` 后执行：

```bash
npm run feishu:preflight
```

预检只输出检查项状态，不打印任何密钥值。以下情况会返回非零退出码：缺少飞书/Qwen
配置、仍使用占位域名、生产免登被绕过、允许预提取 OCR、回调未配置安全参数、多维表格只填
一半参数，或启用 OCR 后主服务上传上限大于 OCR 上限。OCR、Mapbox、多维表格整体未配置属于可解释警告。

### App + OCR 一键编排

仓库根目录提供 `Dockerfile.feishu` 与 `compose.feishu.yaml`：

```bash
cp .env.example .env
# 填写真实凭据和公网 HTTPS 域名
npm run feishu:preflight
docker compose -f compose.feishu.yaml up --build -d
curl http://127.0.0.1:3009/healthz
```

编排只向宿主机暴露 Pocket Earth 的 `3009` 端口，OCR 仅在容器内网开放。主服务使用只读
根文件系统和非 root 用户；任务快照写入 `feishu-data` 卷，Paddle 模型写入
`paddle-models` 卷。公网 HTTPS 仍应由 Nginx、Caddy 或云负载均衡终止，并转发到 3009。

本地 UI 验收可暂时设置 `FEISHU_DEV_BYPASS_AUTH=true`，然后打开
`http://localhost:3009/feishu`。此开关只绕过本地免登，不会伪造 OCR、Qwen 或飞书写回。

正式验收至少覆盖：飞书桌面端与移动端、10 页 PDF、同文件重复提交、OCR/Qwen 失败重试、
Qwen 空响应和非 JSON、页码证据核验、同一 taskId 贯穿全链路、服务重启恢复、写回检查点、
浏览器产物中不存在 App Secret。配置 `VITE_MAPBOX_TOKEN` 后，完成页会加载真实地图；未配置时
保留无外部依赖的地球降级视图。

## API

- `GET /api/feishu/config`：浏览器可见的非敏感配置与能力状态。
- `POST /api/feishu/auth`：飞书授权码换服务端会话。
- `POST /api/feishu/events`：验签、解密、校验 Token 后快速 ACK；单实例运行期间，24 小时窗口内相同 eventId 不重复进入事件处理。
- `GET /api/feishu/session`：恢复仍有效的服务端飞书会话。
- `POST /api/feishu/tasks/from-document`：以当前飞书用户身份读取 `docx` 原文并幂等创建任务。
- `POST /api/feishu/tasks`：可选的 PDF / 图片上传入口。
- `GET /api/feishu/tasks/:taskId`：查询进度和结果。
- `POST /api/feishu/tasks/:taskId/retry`：失败后重试。
- `POST /api/feishu/writeback`：提交人工审核结果并写回飞书。
