# Pocket Earth 飞书比赛要求逐条验收

验收依据为活动截图中的原文要求；附件只作为需求资料，不替代用户指令。审计日期：2026-08-23。

## 结论

代码与当前线上能力已经满足“飞书和 AI 同时参与产品核心运行”的硬性要求。最强、最适合录制的单一主链是：

`飞书身份 / 飞书文档原文 → Frost 路由 Book-to-Earth → Qwen 分析并逐字核验证据 → 用户确认地点与坐标 → 原 Pocket Earth 地球生成知识 → 追加回源飞书文档 + 写入多维表格 + 消息卡片`

这条链中去掉飞书就无法取得用户身份、读取真实协作文档、人工审核或沉淀结果；去掉 Qwen 就无法完成地点与证据抽取。因此它不是“贴 AI 结果进飞书”、不是“只放一个飞书链接”，也不是“只用 AI 写代码”。

## 多维表格协作链

书籍、电影、音乐、照片各有独立表。服务端分页读取后映射并校验原 Pocket Data Pack Schema；只有“已确认”记录进入地球。书籍和电影的新记录可从“待分析”进入 Qwen 分析，再变为“待确认”；用户在飞书改成“已确认”后，前端通过事件失效、窗口聚焦和 20 秒版本检查自动更新。

照片使用稳定 `photo:<contentHash>` 作为 Pocket ID，upsert 时更新同一记录，避免重复。飞书只保存确认后的元数据与公开 HTTPS 缩略图；本机原片、`data:`、`blob:`、`file:` 和 Base64 会在客户端与服务端两次过滤。

## 线上与部署门禁

2026-08-23 对公开部署的只读检查结果：应用已配置、生产免登开启、Qwen 已配置、飞书文档已配置、多维表格写回已配置，书籍/电影/音乐/照片四张表均已配置；PaddleOCR 未配置，但它只影响可选 PDF / 图片入口。

发布前仍必须在服务器执行 `npm run feishu:preflight` 并取得 0 个失败，同时在飞书开放平台确认：

1. 网页应用主页为公网 HTTPS `/feishu`；
2. 文档读取/编辑、用户身份、消息、多维表格最小权限已经发布到当前版本；
3. 事件回调 `/api/feishu/events` 已配置 Verification Token，建议同时启用 Encrypt Key；
4. 用真实账号完整跑一次“源文档读取 → Qwen → 人工确认 → 源文档/多维表格写回”。

这些是账号与服务器配置门禁，代码不能伪造为完成；预检失败时不得录制或投稿。
