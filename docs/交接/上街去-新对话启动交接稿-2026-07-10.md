```text
请接手一个新的产品重构主线，工作名为“上街去”。

先不要修改任何文件、Git、自动化、部署或宣传素材。第一轮只做只读复核，完整读取：

需要评估的两个本地项目：

- 主项目：/Users/zhangcheng/Desktop/Pocket-Earth-GMI
- 旧种诗项目：/Users/zhangcheng/Documents/把所有的诗都种回到地球上_1

请先执行只读检查：

- 两个仓库的 git status、当前分支、remote、最近提交和与 origin/main 的关系
- 当前是否仍有 automation-3 或其他对话在向主项目写入
- 主项目中 ARPhoto、地图 userMarks、FROST 路由、看展搭子和品牌文案的实际边界
- 旧种诗项目的 PRD、PoemPlant 流程、后端和数据模型
- 确认 poem-plant-key.pem 的跟踪状态，但严禁读取或输出私钥内容

产品最新结论：

- Pocket Earth / 口袋地球停止作为任何对外产品名。
- “上街去”目前只是工作名，语义成立，但尚未完成 App Store、安卓商店、商标、域名和账号核查。
- 产品不是普通照片地图，也不是单一诗歌 App。
- 产品主轴是：地球组织知识，AR 让记忆重返现场。
- 推荐表达：“上街去，把知识钉回地球，让记忆重新在场。”
- 地球是远场知识索引；现场 / AR 是近场记忆入口；FROST 与子 agent 负责把内容整理为空间对象。
- 种诗是最有辨识度的招牌 AR 模式，不是空间内核，也不是全产品唯一首屏。

推荐消费级导航：

地球 | 现场 | 我的

- 中间“现场”是默认入口。
- 首屏不能自动请求相机或定位，用户点击“打开 AR”后才索权。
- Agents 是实现机制和比赛能力，后续放入高级入口或深链，不作为普通用户永久一级导航。
- 现场第一版只做两条可靠模式：种一首诗、放一张照片。先完成其中一个纵向闭环，再做另一个。

统一数据模型必须区分：

- knowledgePlace：书、电影、展品、诗等知识对象在世界中属于哪里。
- experienceAnchor：用户在哪里读过、看过、拍过或主动放置它。

一个知识对象可以有多个现场锚点。不是所有知识都必须有 AR。只有用户确认的真实经历或放置点才能写 experienceAnchor，模型不得伪造。

现有 AR 的诚实边界：

- 当前实现有 webxr / pseudo / preview 三模式。
- Web/PWA 只承诺“回到附近后重新贴合”，不承诺跨会话厘米级永久固定。
- iOS 伪 AR 不能宣传为真实持久锚定。
- 如果正式 App 以 AR 为核心卖点，原生 iOS / Android 持久锚定必须单独立项。

种诗项目的处理原则：

- 复用 PRD、四维属性 LUX/TEMP/FLUX/GRAV、经过来源核验的视觉资产和“诗→植物→AR→地点→重访”体验。
- 不复制整套 Figma 应用壳、通用 UI 组件、运行时 Word 段落解析、重复 API wrapper、内存 job 后端和占位 Assistant。
- 先定义 PoemPlantDraft、来源与隐私、plantingPlace / referencedPlaces、状态机、确定性本地兜底和 mock 测试。
- 测试禁止调用真实 GMI、KIRI 或其他付费生成服务。

最高优先级安全阻塞：

- 旧种诗仓库的 poem-plant-key.pem 是已被 Git 跟踪的 RSA 私钥。
- 不得复制、打开、打印或提交它。
- 实施前需要用户安排轮换凭据、从索引和 Git 历史清理，并检查远端与备份。

工程纪律：

- 不要手工复制整个主项目到新文件夹重新维护。
- 先暂停 automation-3 和其他并行写入，再决定迁移基线。
- 使用分支 / git worktree / 正规 clone 保留历史。
- 不覆盖用户或其他对话的改动，不纳入既有未跟踪 .github/。
- 不强推，不部署，不用真实付费 API。
- 不先改所有 UI；先做领域契约和一条可测试纵向闭环。
- 宣传视频放在品牌与 UI 稳定后处理，无旧品牌镜头可复用。

第一轮请只交付：

1. 对备忘录的复核结果：哪些事实仍成立，哪些已过期。
2. 当前两个仓库的安全状态和 Git 并发风险。
3. 三种可行实施路线及明确推荐：
   - Web/PWA 最小可信闭环
   - Web 主体 + 原生 AR 壳
   - 完整原生重构
4. 推荐路线的分阶段计划，每阶段列出修改范围、验收标准、回滚点和是否需要用户决定。
5. 在用户明确回复“开始”之前，不进行任何代码修改。
```
