# “上街去”产品重构备忘录

> 日期：2026-07-10  
> 性质：讨论结论与实施边界，不代表功能已完成  
> 当前工作名：“上街去”；正式商店名、商标和英文名尚未核定

## 1. 一页结论

### 1.1 为什么必须迁移品牌

- 不再把 `Pocket Earth / 口袋地球` 用作 App 名、图标名、官网名、比赛主品牌或公开产品名。
- Apple App Store 已有 GeoMagik LLC 的 `Pocket Earth Maps`、`Pocket Earth PRO`，部分地区直接显示 `Pocket Earth`。对方同属地图、旅行、地点、收藏和地图标记品类，`Maps / PRO` 只是后缀，不足以区分核心品牌。
- 即使某个 localization 暂时允许创建 `Pocket Earth`，也不等于审核、商标和传播安全。Apple 要求应用名独特，并建议避免与现有应用名过于相似。
- `Pocket-Earth-GMI` 可以暂时保留为内部仓库代号；是否修改仓库名、目录、包名、缓存键和域名，应放在用户可见迁移稳定之后。

### 1.2 新产品主轴

工作品牌：**上街去**

产品类别：**AR 空间记忆与个人知识地图**

主叙事：

> 上街去，把知识钉回地球，让记忆重新在场。

短句：

> 知识归于地球，记忆重返现场。

职责分工：

- **地球**：远场知识索引，回答“它在世界里属于哪里”。
- **现场 / AR**：近场记忆入口，回答“我能否回到这里重新遇见它”。
- **FROST 与子 agent**：把照片、诗句、展品、书影音和随手记整理成可确认、可追溯的空间对象。
- **种诗**：最有辨识度的招牌 AR 创作模式，不是全产品唯一功能，也不是空间内核。

### 1.3 与现有产品的区别

- 普通照片地图：按 EXIF 位置回看已有照片。
- 传统地图工具：导航、离线地图、地点和路线。
- “上街去”：把内容转成可放置、可重访的空间记忆；地球负责组织，AR 负责在真实现场重新遇见。

因此宣传和首屏都不应先展示“地区上的照片”，而应先展示现场放置或重逢，再拉远到地球索引。

## 2. 命名结论与未决事项

### 2.1 已决定

- `Pocket Earth / 口袋地球` 停止对外使用。
- “上街去”在产品语义上成立，比“口袋地球”更有行动感，也与走进现实空间、现场重访和城市探索一致。
- 不要为保留旧品牌而使用 `Pocket Earth GMI`、`Pocket Earth 3D` 等变体。

### 2.2 尚未决定

- “上街去”尚未完成中国商标、Apple App Store、主流安卓商店、域名和社交账号的正式核查。
- 公开检索曾发现一个历史安卓购物应用使用“上街去”，这不等于必然不可用，但说明它不是天然空白名称。
- 英文名尚未定稿。若使用当前翻译，`Hit the Streets` 比 `Hit the Street` 更自然；但该英文短语本身也需要核名。
- 在核名完成前，代码里只应使用集中式临时品牌配置，不要把候选英文名散落硬编码到大量组件和文档中。

## 3. 产品信息架构

### 3.1 建议的消费级一级导航

```text
地球            [现场]            我的
EARTH           HERE              ME
```

- 中间“现场”是默认和最突出的入口。
- 首屏不得自动弹出相机授权；先展示附近可重返的记忆和明确的“打开 AR”动作，用户点击后再请求相机权限。
- 地球用于图层、时间线、搜索、关系和导航回地点。
- 我的用于私有资产、草稿、隐私、下载、同步和高级入口。
- `Agents` 是实现机制和比赛演示能力，不宜长期作为普通用户一级导航；可保留深链、调试入口或收入“我的 / 工具”。

### 3.2 现场首发范围

第一阶段只做两个可靠模式：

1. **种一首诗**：诗句变成诗歌植物，用户确认地点后放入现场。
2. **放一张照片**：照片在拍摄地或用户确认的位置重新出现。

看展 3D、声音和其他空间内容后续复用同一套现场锚点，不在第一阶段同时铺开。

### 3.3 首屏与宣传顺序

```text
打开“现场”
→ 选择“种诗”或“放照片”
→ 用户手势打开 AR
→ 在现场放置 / 重新贴合
→ 用户确认保存
→ 拉远到地球与时间线
→ 回到附近后再次召回
```

宣传片前五秒应展示“内容在真实场景中出现”，地图放在闭环后半段。这样无需用解释性文案反驳“Apple Photos 也有照片地图”。

## 4. 统一领域模型

### 4.1 不能再把一个经纬度承担所有含义

```ts
interface SpatialArtifact {
  id: string;
  kind: 'poem' | 'photo' | 'exhibition' | 'book' | 'movie' | 'music' | 'note';
  title: string;
  createdAt: string;
  privacy: 'private' | 'unlisted' | 'public';
  provenance: Record<string, unknown>;
  knowledgePlaces: KnowledgePlace[];
  experienceAnchors: ExperienceAnchor[];
}
```

### 4.2 两类空间关系

`KnowledgePlace`：知识对象在世界结构里属于哪里。

- 书的故事地、作者地
- 电影取景地、故事地
- 展品所在展馆、出土地
- 诗中提及的地点

`ExperienceAnchor`：用户真实经历或主动放置的现场。

- 我在哪里读过这本书
- 我在哪里看过这个展品
- 这张照片在哪里拍摄
- 我把这首诗种在了哪里

一个知识对象可以有多个现场锚点；并非所有知识都必须有 AR。只有用户确认的经历或放置点才能写入 `ExperienceAnchor`，模型不得伪造。

### 4.3 现场锚点最小字段

```ts
interface ExperienceAnchor {
  id: string;
  geo: { lat: number; lng: number; accuracy?: number };
  pose?: {
    position: [number, number, number];
    quaternion: [number, number, number, number];
  };
  mode: 'native' | 'webxr' | 'pseudo' | 'preview';
  confirmedByUser: boolean;
  createdAt: string;
  mediaRefs: string[];
  revisitPolicy: 'nearby-replace' | 'persistent-anchor';
}
```

原则：地球钉点不是 AR 位姿；GPS 附近判断也不是厘米级持久锚点。

## 5. AR 真实能力边界

### 5.1 当前已有能力

现有实现已经区分：

- `webxr`：支持时进入 WebXR 放置。
- `pseudo`：相机背景加内容叠加，必须明确标为伪 AR。
- `preview`：无相机或桌面环境下的 3D 预览。

相关文件：

- `src/app/lib/arphoto/types.ts`
- `src/app/lib/arphoto/capability.ts`
- `src/app/components/ARPhotoView.tsx`
- `src/app/components/ARPhotoRunPage.tsx`
- `docs/AR照片/重返现场-设计.md`

### 5.2 当前不能承诺

- 不能承诺关闭 App 一个月后在原位置厘米级复现。
- 不能把 iOS 相机叠加宣传成真实持久 AR 锚定。
- 不能在页面加载时自动请求相机或定位权限。
- 不能把没有真实地点或用户确认的知识记录伪造成现场记忆。

### 5.3 对外诚实口径

当前 Web/PWA 阶段：

> 回到附近后，举起手机重新贴合这段记忆。

正式 App 若以 AR 为核心卖点，路线必须包含原生 iOS / Android 持久锚定能力。原生化是独立阶段，不能与品牌文字替换混成一次大改。

## 6. “种诗”子 agent 的定位

### 6.1 为什么值得成为招牌子 agent

- 它完整覆盖“输入内容 → AI 理解 → 生成资产 → 绑定地点 → AR 放置 → 地球归档 → 附近重访”。
- 它让产品从“照片地图”变成“空间创作与记忆召回工具”。
- 它与“上街去”的行为召唤、城市现场和个人知识库叙事一致。

### 6.2 应抽取的领域链路

```text
诗句 / 摘录
→ 记录作者、来源和公开范围
→ LUX / TEMP / FLUX / GRAV 可解释分析
→ 模板生成或云端增强
→ PoemPlantDraft
→ 用户确认 plantingPlace
→ 预览 / AR 放置
→ 写入 ExperienceAnchor
→ 钉回地球、时间线和个人花园
```

必须区分：

- `plantingPlace`：用户实际种植地点，进入现场锚点。
- `referencedPlaces`：诗中提及的地点，只作知识关系。
- `original / excerpt`：原创还是摘录。
- `analysisSource / renderSource`：本地、模板、GMI 或其他来源。
- `private / public`：个人知识库默认私有，公开内容需要来源与权限边界。

### 6.3 不应直接复制旧诗歌 App

旧项目：`/Users/zhangcheng/Documents/把所有的诗都种回到地球上_1`

值得复用：

- PRD 中的地点锚定、Nearby、个人花园和诗歌植物概念。
- LUX / TEMP / FLUX / GRAV 四维语义。
- 经过来源核验的视觉模板、动画与交互资产。
- “诗 → 植物 → AR → 地点 → 重访”的体验顺序。

不能原样搬入：

- Figma 同步生成的整套应用和大量通用 UI 组件。
- 运行时从文档段落解析诗歌数据的 `MeTab.tsx` 逻辑。
- 两套重复 API wrapper 和宽泛 `any` 数据结构。
- 当前 FastAPI 内存任务、未区分真实 template / assistant 的 `generator`、FFmpeg 占位输出。
- “模型端点待接”的 Assistant 演示界面。

先定义并测试 `PoemPlantDraft`、确定性本地兜底、失败状态和 suggest-then-confirm 钉点，再接 UI。

## 7. 严重安全阻塞

旧诗歌仓库根目录存在 `poem-plant-key.pem`：

- 已通过 `file` 确认为 PEM RSA 私钥。
- 已被 Git 跟踪，并存在于 Git 历史。
- 本轮评估没有读取私钥内容。

任何复制、公开、迁移或新仓库初始化之前必须：

1. 确认私钥用途并立即轮换对应服务器凭据。
2. 从当前索引移除并加入 `.gitignore`。
3. 使用合适工具清理 Git 历史中的私钥。
4. 核查远端、备份、CI 日志和共享压缩包是否含旧私钥。
5. 清理后重新验证部署连接，禁止继续使用旧密钥。

这是迁移前置阻塞，不是普通待办。

## 9. 推荐迁移顺序

### 阶段 0：做决定前的门禁

1. 完成“上街去”及候选完整名的商店、商标、域名和账号核查。
2. 暂停 `automation-3` 和其他写入同仓库的对话。
3. 轮换并清理旧诗歌仓库私钥。
4. 对比当前工作分支与 `origin/main`，确定不会丢失看展搭子、AR 照片和 GMI 能力的基线。

### 阶段 1：只建契约，不改大 UI

1. 定义 `SpatialArtifact`、`KnowledgePlace`、`ExperienceAnchor`。
2. 定义 `PoemPlantDraft` 和 agent contract。
3. 为地点语义、用户确认、失败兜底、隐私默认值和来源追踪写测试。
4. 测试全部 mock，不调用真实 GMI、KIRI 或其他付费服务。

### 阶段 2：跑通最小现场闭环

1. 新增“现场”入口，默认打开但不自动索权。
2. 复用现有 ARPhoto 的能力检测、三模式和清理纪律。
3. 先完成“放一张照片”或“种一首诗”其中一个纵向闭环，再做另一个。
4. 用户确认后同时保存现场锚点与地球索引，并可双向跳转。

### 阶段 3：迁移种诗

1. 只提取领域逻辑与已核验资产，不复制旧应用壳。
2. 本地模板先可用，云端增强失败不阻塞主闭环。
3. 建立结构化存储，停止运行时解析 Word 段落。
4. 接入 FROST 显式入口和有限意图路由，避免与普通“记一笔”重叠。

### 阶段 4：品牌与消费级导航

1. 将用户可见名称集中到品牌配置和商店元数据。
2. 导航逐步迁为 `地球 | 现场 | 我的`。
3. `Agents` 保留为深链 / 高级入口；照片降为地球图层与子 agent。
4. 清理用户可见 `Pocket Earth / 口袋地球`，内部包名和缓存键可延后。

### 阶段 5：宣传与原生路线

1. 界面、品牌和演示闭环稳定后再重做片头、配音和含旧品牌镜头。
2. 无旧品牌的功能素材可以复用，不默认全部推倒。
3. 原生 iOS / Android 持久锚定单独立项、单独验收。

## 10. 验收标准

- 新用户第一眼看到“现场”真实操作，不是照片地图或营销落地页。
- 相机和定位只在用户手势后请求；拒权、无 HTTPS、无 WebXR 都有可见降级。
- 一个内容对象能同时表达知识地点与个人现场，两者不会互相覆盖。
- 用户确认前不写地球、不写现场锚点。
- 失败、生成中和伪 AR 不会被展示成已完成的真实持久 AR。
- 种诗在无云端模型时仍可通过本地模板完成闭环。
- 现场锚点与地球钉点可双向跳转、删除一致、无孤儿数据。
- iOS / Android / 桌面三种能力口径诚实。
- 相关单测、AR/poem 领域测试和 `npm run build` 通过。
- 测试不消耗真实 GMI / KIRI / 生成服务额度。
- 仓库与构建产物中不存在私钥、token 或大体积原始相机数据。

- 不要手工复制整个仓库到新文件夹再从头维护。
- 不要丢失 Git 历史；需要新目录时使用迁移分支、worktree 或正规 clone。
- 不要在核名前全量硬编码“上街去 / Hit the Streets”。
- 不要把旧诗歌 App 整仓塞进主仓库。
- 不要自动给知识对象生成虚假的现场位置。

- 不要边跑 `automation-3` 边在另一个窗口修改同一批热区。
- 不要在完成 UI 和能力验收前重录整条宣传视频。
- 不要部署，不要调用真实付费 API，不要强推 Git。
