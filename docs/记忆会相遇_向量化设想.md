# 记忆会相遇 · 向量化设想与落地路线

> 面向路演/决赛的功能说明。核心判断：**"记忆彼此相遇"这个产品能力现在就能在 UI 上体现，而且第一版不需要向量**；语义向量是后续的增强层，按信号触发再上。

---

## 一句话设想

> **地理坐标让记忆落地，时间坐标让记忆生长，语义坐标让记忆相遇。**
> Pocket Earth 的每一段记忆都同时活在这三套坐标里——你在哪记的、什么时候记的、它在你的精神世界里靠近什么。

---

## 现在就能演示的（已在代码里，零模型）

打开地球上任意一条记忆，卡片底部多出一节 **「相关记忆 · MEMORIES MEET」**：它把这条记忆和你其它的记忆连起来——

- 一件宋代官窑瓷 → 关联出**同一周看的另一件宋瓷**（"都是宋 / 都是瓷器"）、**同城读的《东京梦华录》**（展↔书的跨域回声）。
- 每条只给**人话理由**（"就在同一处""同一周记的""都是宋"），**不显示任何相似度百分比**。
- **"你记的"和"看过/读过"措辞分开**，绝不把资料库里看过的电影说成你到过的地方。
- 没结果就整节不出现——不留死按钮。点一条相关记忆，直接飞到地球上那个点、顺藤摸瓜。

**它怎么算的**：地理邻近 + 时间邻近 + 结构化标签共现（朝代/流派/导演/器类，用你的口味画像加权）+ 中文字符 2-gram 文字相近。**零模型下载、零网络、原文不出设备、离线即用。**

> 这是本产品相对纯文本笔记应用的结构性优势：flomo 的笔记只有文字，所以它"最底层的能力是向量化"（少楠原话）；Pocket Earth 的笔记天生带经纬度、时间、结构化标签——**我们最底层的能力是结构化关联，向量只是后续的补丁。**

## 后续：语义坐标（端侧嵌入，按信号触发）— 决赛深度

第一版覆盖不了的场景：两条**措辞完全不同、地点时间标签都不沾边、但在讲同一种感受**的记忆（写"失眠"的和写"睡不着"的）。这才需要真正的语义向量。路线：

1. **触发条件（而非一上来就做）**：第一版上线后，统计"用户手动关联、但四路结构化信号全零分"的记忆对——这个**语义缺口计数**累积到肉眼可见，才值得引入嵌入。不给不存在的问题提前买单。
2. **怎么做轻**：端侧 `transformers.js` 加载小型量化嵌入模型，与 Google Gemma 的本地优先策略使用同一套加载与降级边界。每条记忆生成一次 512 维向量，存在浏览器 IndexedDB，原文与向量都不出设备。
3. **为什么不用向量数据库**：个人规模（几千条）下，纯 JS 暴力余弦一次查询 <10ms（实测 1 万条×512 维也就 20MB、<10ms）。HNSW/pgvector 这类是为百万级设计的，在这个量级是负资产。这也和《AI 工程》的建议一致：先词法、真需要语义再上嵌入、小数据集用精确检索即可。
4. **不做的事**：不做把全部笔记上云的服务端向量库（违背"不出设备"）；不做"相似度百分比"；不把它做成又一个要用户手动打开的端侧引擎开关，而是在相关区块出现语义缺口时**就地提议**下载。
5. **混合排序**：语义分只是加入现有四路信号的又一路，权重靠上线后的点击/确认数据来调，不靠拍脑袋的公式。

> 一句话：**管道已经铺好了**（`EdgeModel.embed` 契约、`/api/edge` 的 embed 分发都在，只是当前空转），要接语义坐标是一天的活，但先把我们独有的结构化牌打完。
