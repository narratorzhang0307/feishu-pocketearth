# Pocket Earth · 审核矩阵

审查基线：2026-07-14

目标：把 Google 技术审核的五项标准，逐条映射到产品问题、现场交互、Google 技术、代码证据、屏幕证据与诚实边界。

## 1. 一句话审核叙事

Pocket Earth 是“基于空间的个人知识库”：它用 Gemma 在浏览器内处理私密、高频、弱网任务，用 Gemini 处理复杂多语、多模态与跨文化叙事，再把 AI 生成的草稿交给用户确认，最终把书、影、音、旅、照片和展览记忆钉回一颗私人地球。

审核时应始终讲同一条因果链：

```text
文化记忆被平台切碎
  → 地球成为跨媒介统一索引
  → Gemma / Gemini 分工提取与理解
  → Boundary + Critic + RunTrace 保证可控、可见
  → 用户确认后形成可回访的空间记忆
  → 帮助跨文化用户理解“我在哪里遇见了什么”
```

## 2. 五项审核总表

| 审核维度 | 权重 | 审核人员真正要确认什么 | Pocket Earth 的核心回答 |
|---|---:|---|---|
| 完成度与表达 | 25% | 是否真能运行；3–5 分钟能否走通主价值；材料能否讲清问题、方案、亮点 | 可运行 PWA；看展从输入、推理、草稿、确认到地球详情完整闭环；RunTrace 让过程可见 |
| Google AI / 产品工具深度 | 25% | Google 技术是否承担核心能力，而非简单套壳；选型是否与场景匹配 | Gemma + MediaPipe 真端侧；Gemini 按 route / multilingual / narrative / council 分层；视觉、JSON、多语、叙事与合议形成完整系统 |
| 创新与 Vibe Coding | 20% | 是否从具体海外用户痛点出发；功能、交互、AI 用法是否有差异化与现场冲击 | 从“聊天框”转向“空间知识库”；文化对象统一钉回地球；双推理平面和实时编排树构成独特交互 |
| Tech for Good | 20% | 是否服务真实人群与真实场景；是否可落地；是否有清晰影响路径和扩展方式 | 面向文化旅行者、海外学习者、跨文化家庭及弱网/隐私敏感用户；端侧优先、手填可用、用户控制数据 |
| 跨文化同理心与本地化 | 10% | 是否超越直译；是否尊重当地语境、习惯与情感；是否避免刻板印象 | 中英导览 + 时间线 + 事实型文化桥；当前语境优先；禁止国族性格推断；展品钉到实际观看的展馆 |

## 3. 审核证据闭环原则

每个重点声明都使用五列证据，不只展示一张架构图：

| 层 | 要回答的问题 | 例子 |
|---|---|---|
| 问题 | 为什么值得解决 | 展签照片、旅行、书影音分散在不同平台 |
| 交互 | 用户实际做了什么 | 拍公开展签、看到草稿、修正、确认、飞到地球 |
| Google 技术 | 模型为何参与 | Gemma 端侧读图，Gemini 补全与跨文化叙事 |
| 代码 | 实现在哪里 | `gemmaEdge.ts`、`agent.ts`、`curator.ts`、`pin.ts` |
| 屏幕 | 审核人员如何确认不是口播 | 端侧模型“运行中”、RunTrace、确认弹窗、地图详情 |

一项能力如果无法同时回答这五列，就不应作为主申报点。

## 4. 审核一：完成度与表达（25%）

### 4.1 官方要求的产品含义

- 核心功能必须真实运行，不是 PPT、静态页或只有概念；
- 交互顺畅，3–5 分钟演示能呈现主要价值；
- 对外作品、视频和文字应清楚说明问题、方案和亮点。

### 4.2 当前产品证据

#### 可运行产品

- React + TypeScript PWA；
- Photos / Earth / Agents 三个入口；
- 书、电影、音乐、照片、旅行、展览、通用记录、AR 照片等领域运行页；
- 浏览器内 Gemma 控制面板；
- Gemini 服务端代理；
- 地图落点、详情、移除与本地持久化；
- 端侧 3D Blob 导入与展示；
- RunTrace、错误边界、模型降级和健康记录。

#### 完整主闭环

看展搭子可从一句话或展签图片开始，最终产生一个真实的空间对象：

| 阶段 | 屏幕结果 | 代码证据 |
|---|---|---|
| 输入 | 文字、端侧拍展签、云识别或手填 | `ExhibitionRunPage.tsx` |
| 感知 | 候选展品名与脱敏展签文本 | `sense.ts`、`visionRead.ts` |
| 补全 | 中英文名、朝代、材质、器类、文明、展馆等 | `tagging.ts`、`enrichEntity.ts` |
| 校验 | 朝代表、展馆表、历史纠错、置信度 | `catalog.ts`、`venues.ts`、`critic.ts` |
| 跨文化 | 中英导览、时间线、文化桥 | `curator.ts` |
| 审计 | 阶段、耗时、Gemma/Gemini/本地/fallback | `bus.ts`、`RunTrace.tsx` |
| 决定 | 用户修正、存档或确认 | `ExhibitionRunPage.tsx` |
| 写入 | 展馆坐标、地球点、领域索引、脱敏画像 | `pin.ts`、`markPlace.ts` |
| 回访 | Earth 中打开展品详情 / 时间线 / 3D | 地图与展品详情组件 |

### 4.3 现场演示动作

推荐只演示一个完整闭环，不在 4 分钟内快速点完所有 agent：

1. Earth 首页：一句话解释“这不是聊天框，是空间知识库”；
2. Agents：展开端侧引擎，确认 Gemma 为“运行中”；
3. 看展搭子：输入展品，或选择公开展签；
4. 指向 RunTrace：说明哪一步端侧、哪一步云端、哪里发生降级；
5. 展示四字段和结构化标签；
6. 修改一项字段或评分，强调用户决定；
7. 确认钉到展馆；
8. 飞回 Earth，打开详情完成回访。

### 4.4 自动验证

```bash
npm run typecheck
npm test -- --run
npm run build
node --check server.mjs
```

当前基线：

- 52 个测试文件；
- 1336 项测试；
- 类型检查通过；
- 生产构建通过；
- 2246 个模块完成转换；
- 生产服务语法检查通过。

### 4.5 对外表达注意

- 开场先讲用户问题，不从模型名开始；
- 一个场景贯穿到底，其他 agent 只在结尾说明扩展性；
- 每次出现模型名，都紧跟“它在产品里具体做什么”；
- 不把测试数字当作产品价值本身，测试只用于证明完成度；
- 小红书/报名平台的发布与链接属于仓库外提交动作，不能因为仓库内有素材就表述为“已经发布”。

## 5. 审核二：Google AI / 产品工具深度（25%）

### 5.1 官方要求的产品含义

- 看 Google 技术使用的广度与深度；
- Google 技术需要构成核心能力，而非只做一次文本生成；
- 可综合使用模型能力、工具链、开发效率、部署或多模态；
- 必须解释为什么该技术适合该场景。

### 5.2 Google 能力分工

| Google 技术 | 核心任务 | 不是装饰的理由 | 屏幕/接口证据 |
|---|---|---|---|
| Gemma 3n E2B | 分类、排序、短对话、视觉读图 | Router 与 `visionRead` 直接依赖其契约；隐私输入可不离设备 | 端侧面板、真实回答耗时、RunTrace Gemma 徽章 |
| MediaPipe LLM Inference | 在浏览器内加载 Web Gemma | 通过 `LlmInference.createFromOptions` 和 GPU delegate 真运行，无 `/api/edge` | 加载进度、模型运行中、独立 WASM |
| Gemini Flash-Lite | 长尾意图路由 | 只在规则与端侧没有结果后处理自然语言，并受城市复核护栏约束 | Router trace 与 task model |
| Gemini Flash | 多模态、结构化、多语与叙事 | 看展从云视觉到受控字段和四字段导览均由其承担 | 草稿字段、四字段、provider metadata |
| Gemini Pro Preview | 复杂法庭合议 | 显式 `task=council` 的法庭阶段进入 Pro 档 | 法庭流程与 task 请求 |
| Gemini Image | 可选明信片图像 | 与主闭环解耦，不用图像生成掩盖核心功能 | `/api/gemini-image` 返回 metadata |

### 5.3 深度证据一：不是“所有任务都发给同一个模型”

Router 顺序：

```text
规则快路
  → Gemma 端侧预分类
  → 隐私护栏
  → Gemini Flash-Lite 长尾路由
  → 本地规则兜底
```

模型 task 表：

| Task | 模型 | 代码 |
|---|---|---|
| route | `gemini-3.1-flash-lite` | `taskModels.ts`、`llmRoute.ts` |
| multilingual | `gemini-3.5-flash` | `tagging.ts`、`enrichEntity.ts` |
| narrative | `gemini-3.5-flash` | `curator.ts` |
| council | `gemini-3.1-pro-preview` | `courtroom/stages.ts` |

选择依据是任务复杂度、隐私、延迟和输出契约，而不是把所有请求堆进最强模型。

### 5.4 深度证据二：Gemma 端侧链路可验证

| 证据 | 当前实现 |
|---|---|
| 模型 | `gemma-3n-E2B-it-int4-Web.litertlm` |
| 大小 | 3,038,117,888 字节 |
| SHA-256 | `b6c8e1081ec80730f14473a5ece941b48da5d8e2a80c97c2963da153f3eff3d2` |
| runtime | `@mediapipe/tasks-genai` |
| delegate | GPU |
| 浏览器要求 | WebGPU |
| 模型来源 | 项目固定 URL或用户本机文件 |
| 权重服务 | same-origin、HEAD、GET、Range 206 |
| 能力 | available / chat / classify / rank / vision |
| bundle | 权重不在 Git 与 `dist`；MediaPipe 动态分块 |

现场可按“加载模型 → 运行中 → 端侧试一句 → 显示毫秒耗时”的顺序演示。

### 5.5 深度证据三：多模态不是直接 OCR 后结束

公开展签进入系统后：

1. Gemma 端侧视觉读字；
2. 确定性脱敏；
3. Gemini 结构化为受控实体字段；
4. 本地目录与用户历史纠错；
5. Gemini 生成跨文化四字段；
6. 用户修正；
7. 统一空间写入；
8. 长期画像只回流公开标签。

这是“视觉 → 结构 → 文化语境 → 空间记忆”的多阶段产品能力，不是把图片交给模型后展示一段回复。

### 5.6 Provider 真实性

| 配置 | 实际传输 | 模型约束 |
|---|---|---|
| 有 `GEMINI_API_KEY` | Google 官方 Gemini API | `gemini-*` |
| 无官方 key、有 `GMI_API_KEY` | GMI 备用传输 | `google/gemini-*` |
| 都没有 | 返回空结果并本地降级 | 不伪造模型结果 |

接口把 `provider`、`modelOwner`、`transport` 分开返回。审核现场应优先使用官方 key，展示：

```json
{
  "provider": "Google Gemini API",
  "modelOwner": "Google",
  "transport": "google-gemini-api"
}
```

### 5.7 不能声称的 Google 技术

当前代码没有接入：

- Google Search Grounding；
- Vertex AI；
- Firebase；
- Flutter / Android Studio；
- Google ADK；
- 端侧向量搜索或端侧 RAG。

Google 工具的“广度”不能靠列举未使用产品获得；本项目的优势应放在 Gemma + MediaPipe + Gemini 的深度协作。

## 6. 审核三：创新与 Vibe Coding（20%）

### 6.1 官方要求的产品含义

- 从具体海外用户或跨文化场景的痛点出发；
- 在功能、UI、体验、AI 使用或本地化上有明显差异；
- 适合现场演示，体现 AI 让产品边界扩展。

### 6.2 创新一：空间不是背景，是数据模型

许多 AI 产品将地图作为结果页，Pocket Earth 把地点作为跨媒介主索引：

```text
书的故事地 / 作者地
电影的取景地 / 故事地
音乐的艺人地 / 歌曲城市
照片的拍摄地
旅行的目的地
展品的实际观看展馆
  ↓
统一 userMarks + MarkerKind + markPlace
```

差异不在“有一个地球动画”，而在多个领域使用同一坐标写入契约、幂等主键、详情 meta 和回访入口。

### 6.3 创新二：端云双平面是产品交互

用户能看到并控制：

- 是否加载 Gemma；
- 模型是否在本机运行；
- 没有 WebGPU 或模型时如何降级；
- 公开展签是否同意云识别；
- RunTrace 中每一步在哪里计算；
- 最终是否写入地球。

推理位置不只是后台优化，而是用户界面的一部分。

### 6.4 创新三：RunTrace 把“智能体编排”变成可见体验

传统 demo 只展示最终答案；Pocket Earth 展示：

- agent 根运行；
- 子 skill 阶段；
- 相邻阶段耗时；
- Gemini / Gemma / 本地徽章；
- fallback；
- 最终成功或失败。

这使审核人员能直接区分“模型做了什么”和“本地规则做了什么”。

### 6.5 创新四：suggest-then-confirm

Agent 不直接更改私人地球：

```text
感知
  → 建议草稿
  → Critic / Validator
  → 用户修正
  → Confirm Gate
  → markPlace
```

AI 的价值是降低整理成本，而不是替用户夺走决定权。

### 6.6 Vibe Coding 的正确表达

可以强调：

- 从“私人地球”的产品直觉出发，反向长出跨领域数据契约；
- 先让核心闭环能运行，再用测试把模型、隐私与降级固化；
- UI 的像素电台、私人地球、展览时间线和运行树构成一致体验；
- 多 agent 按文化对象与任务边界承担单一职责，数量不作为能力指标。

不应只说“代码由 AI 生成很多”。审核关心的是产品直觉如何被快速变成可运行、可验证的系统。

## 7. 审核四：Tech for Good（20%）

### 7.1 官方要求的产品含义

- 服务真实人群、弱势群体、低资源或全球场景；
- 在目标市场具有可行性，而不只是善意故事；
- 目标用户、使用场景、影响路径与扩展计划清晰。

### 7.2 目标用户

| 用户 | 现实处境 | Pocket Earth 的帮助 |
|---|---|---|
| 文化旅行者 | 旅行结束后照片与展签失去地点语境 | 以展馆、城市和时间线重新组织 |
| 海外学生 / 居民 | 在不同语言和文化系统之间生活 | 中英导览与文化桥保留语境，而非只直译 |
| 跨文化家庭 | 家庭成员的语言和文化背景不同 | 同一空间对象提供多语、事实型解释 |
| 弱网用户 | 博物馆、旅途中网络不稳定 | Gemma、本地目录、缓存和手填保证基本可用 |
| 隐私敏感用户 | 不愿把私密图片、证件或记忆全部上传 | 原图端侧优先、单次用途授权、用户确认写入 |

### 7.3 影响路径

```text
碎片化记录
  → 结构化文化对象
  → 空间和时间锚点
  → 可回访的私人记忆
  → 理解作品/展品与地点的联系
  → 更有同理心的跨文化理解
```

这个路径的每一步都有产品对象：

- 碎片：文字、照片、展签；
- 对象：`ArtifactDraft` 和其他领域实体；
- 空间：`GeoTarget`、`userMarks`；
- 时间：visitDate、eraStart / eraEnd；
- 回访：Earth 详情、展览时间线、3D；
- 文化理解：四字段导览。

### 7.4 可行性证据

- 浏览器 PWA，无需安装原生客户端；
- 数据默认在浏览器；
- 无 Gemini key 时仍有规则、目录、缓存和手填；
- 无 WebGPU 时仍可使用云端非隐私能力或手填；
- 模型权重独立部署，不拖入应用 bundle；
- 重任务按 task 路由，避免所有请求使用 Pro；
- 已补全实体优先命中本地索引，减少重复成本；
- 3D 是可选增强层，不阻断主闭环；
- 可从展览扩展到书、影、音、旅和照片，因为共用空间写入契约。

### 7.5 不能夸大的社会价值

- 不是医疗、法律或公共安全系统；
- 不声称代替博物馆学者或权威馆藏数据库；
- 文化桥基于输入事实，不能保证补齐所有历史争议；
- 弱网可用不等于首次加载 2.8 GiB 模型不需要网络或预装；
- 浏览器本地存储不是跨设备云备份；
- 影响指标目前是产品路径与可运行证据，不应虚构用户规模和社会数据。

## 8. 审核五：跨文化同理心与本地化（10%）

### 8.1 官方要求的产品含义

- 内容、语言、UI 与交互尊重目标市场习惯；
- 不停留在机械翻译；
- 理解当地语境、习惯与情感。

### 8.2 四字段设计

| 字段 | 作用 | 防止的问题 |
|---|---|---|
| 中文私人导览 | 解释“为什么值得看” | 只有数据库式字段，没有人的观看入口 |
| English guide | 为不同语言用户提供事实一致的短导览 | 只显示中文或逐字直译 |
| 时间线位置 | 将展品放进文明、时代、材料或地点关系 | 失去历史语境 |
| 文化桥 | 解释共同主题或可核实差异 | 用国族标签和刻板印象制造“文化感” |

### 8.3 Prompt 与代码护栏

`curator.ts` 要求：

- 不编造未给事实；
- 不确定时围绕材料、时代、展馆和观看方式；
- 文化桥只能基于已知事实；
- 禁止国族性格推断和刻板印象；
- 3D 只说“可旋转观看”，不夸大精度；
- 中英导览在同一次调用中生成，减少跨调用事实漂移。

### 8.4 本地化不是只换语言

当前实现还包括：

- 展品钉到“用户实际观看的展馆”，而不把出土地当作唯一地点；
- 朝代键使用本地受控目录，保证中文时间线排序；
- 输入可识别中英文展签与字段别名；
- 当前表达与旧画像冲突时，以当前表达为准；
- 展馆别名规范化，减少“国博 / 国家博物馆”等本地称呼差异；
- 用户可手动修正地点、评分和展品字段；
- 文化桥在事实不足时允许缺失或使用克制本地模板。

### 8.5 现场展示方式

不要只展示“把中文翻成英文”。应同时指向：

1. 结构化标签；
2. 中文导览；
3. English guide；
4. 时间线；
5. 文化桥；
6. 用户确认；
7. 实际观看展馆的地图点。

这样审核人员看到的是“跨语言 + 历史语境 + 空间语境 + 人类控制”。

## 10. 五分钟现场脚本

### 0:00–0:25 · 问题与定位

屏幕：Earth 首页或图 01。

建议表述：

> 我们的文化记忆被照片、地图、书影音和展览平台切碎。Pocket Earth 把这些碎片整理成一颗可以持续写入、确认和回访的私人地球。

### 0:25–0:50 · Google 双推理平面

屏幕：Agents 端侧引擎。

动作：

- 展开 Gemma 面板；
- 显示“Gemma 3n E2B × MediaPipe”；
- 确认运行中，必要时端侧试一句。

建议表述：

> 私密、高频和弱网任务优先在浏览器内由 Gemma 处理；复杂多语和跨文化叙事再交给 Gemini。端侧失败不会静默上传。

### 0:50–2:20 · 看展主闭环

屏幕：Exhibition Agent。

动作：

1. 输入一句展品描述或选择公开展签；
2. 若展示云视觉，停在二次确认弹窗 2 秒；
3. 查看 RunTrace；
4. 展示结构化字段和四字段；
5. 修改评分或地点；
6. 确认钉地球。

建议表述：

> Gemma 先在端侧读图；只有公开展签且我明确同意，图片才会进入 Gemini。Gemini 不是只写一句文案，它补全受控字段，并一次生成中英导览、时间线和事实型文化桥。

### 2:20–2:55 · 回到地球

屏幕：Earth 展馆落点与详情。

动作：

- 飞到展馆；
- 打开刚写入的展品；
- 指向时间线、标签或 3D 入口。

建议表述：

> 最终写入的是带地点、时间、来源和个人评分的空间对象。AI 只提出草稿，用户确认后才进入私人地球。

### 2:55–3:25 · 工程可信度

屏幕：RunTrace 或图 07。

建议表述：

> Harness 把规则、Gemma、Gemini、校验和写入串成可观察的执行树。没有 key、没有 WebGPU 或定位失败时，系统会明确降级，而不是伪造结果或白屏。

### 3:25–4:00 · 社会价值与扩展

屏幕：地球上不同类型的点，或图 02 / 图 08。

建议表述：

> 这套空间契约已经扩展到书、电影、音乐、照片和旅行。它服务文化旅行者、海外学习者、跨文化家庭，以及弱网和隐私敏感场景，让分散的文化碎片重新成为可理解、可回访的个人记忆。

## 11. 演示备用路径

| 现场问题 | 备用动作 | 可以怎么说 |
|---|---|---|
| Gemma 首次加载慢 | 提前加载；或选择本机模型；保留模型面板证据 | 模型在浏览器本机运行，首次加载是 2.8 GiB 权重成本 |
| 设备无 WebGPU | 展示“不支持”提示和规则兜底；使用云端非隐私输入 | 系统明确降级，不把本地失败伪装成端侧命中 |
| Gemini 网络异常 | 使用本地 demo 草稿或本地导览；指向 fallback RunTrace | 主闭环仍能完成，云能力是增强而非单点崩溃 |
| 展签读不出 | 手填展品名；或演示公开展签二次确认云识别 | 手填是正式兜底，不需要强迫上传图片 |
| 自动定位失败 | 在 UI 选择展馆/城市 | 无坐标不自动落点 |
| 3D 太重 | 展示内置 preset 或一张普通展品卡 | 3D 是增强层，结构化记忆和空间闭环不依赖它 |

不要在失败后说“其实后台已经跑了”。直接展示降级也是架构深度证据。

## 13. 声明—证据—边界矩阵

| 可说的声明 | 直接证据 | 必须同时说清的边界 |
|---|---|---|
| Gemma 在浏览器端运行 | MediaPipe `LlmInference`、WebGPU、无 `/api/edge` | 需要兼容设备和已安装/选择的 Web 权重 |
| Gemini 是云端核心能力 | taskModels、provider adapter、展览与法庭调用 | 无 key 时会降级；不是所有请求都走云 |
| 官方 Gemini API 优先 | provider 选择逻辑和 response metadata | GMI 只是没有官方 key 时的备用传输 |
| 图片默认不出端 | `visionRead` 与图片 consent | 用户明确同意的公开展签可进入云视觉 |
| AI 不自动改私人地球 | draft、Validator、confirmPin、markPlace | 用户确认后才写入；不是全自动执行系统 |
| 支持长期记忆 | 标签计数、fingerprint、空间索引 | 不存全部原始对话；当前以单设备浏览器为主 |
| 支持跨文化导览 | 四字段 prompt 与 tests | 基于输入事实，不替代权威研究 |
| 支持 3D 展品 | 本地导入、IDB Blob、viewer | KIRI 是非 Google 可选增强，Google 版默认关闭 |
