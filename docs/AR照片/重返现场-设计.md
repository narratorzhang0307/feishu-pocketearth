# 重返现场（AR 照片 agent）· 设计文档

> 2026-07-05。任务来源：docs/交接/项目全景交接-2026-07-05.md §9 + 用户口头交代
> （"照片固定到现实，别做诗歌那么文艺；博主 XOSMO Lab 的做法太重；一定要解耦"）。

## 0. 一句话

地球是**远场索引**（在星球上找回"它在哪"），重返现场是**近场重访**（站回原地，照片悬浮在它被拍下的地方）。
同一哲学的两个尺度：地球钉经纬度，AR 钉现实空间。

## 1. 可行性判断（为什么真做而不是概念占位）

对标 XOSMO Lab「流动摄影个展」（小红书，2026-04）：他们 Blender 手工搭"垂吊照片墙"3D 场景
→ 上传小程序 AR 系统适配（几轮调整）→ 手机平面 AR（对准地面→点击放置→单指旋转双指缩放）。

**拆解后发现 Blender 在链路里只干一件事：排照片平面的空间布局。** 这可以程序化生成
（`layout.ts` 布局引擎，确定性算法）。他们最终的手机体验就是平面检测 AR ——
恰好是安卓 Chrome WebXR `immersive-ar` + hit-test 的标准能力（用户主力机是安卓）。

结论：**纯 Web、零 Blender、零小程序、零新依赖**（three 0.185 已在栈内）可以做出同等体验。
不是概念占位，是可运行 v1；概念留白只在"跨会话厘米级锚点"（见 §5 诚实边界）。

## 2. 三模式一套场景（无死按钮）

同一个 three.js 照片场景（布局引擎产出的像素风拍立得相框群），三种呈现按能力自动分流：

| 模式 | 条件 | 体验 |
|---|---|---|
| `webxr` AR·现实锚定 | 安卓 Chrome，`isSessionSupported('immersive-ar')` | hit-test 找平面 → 点击放置 → 走近观看 |
| `pseudo` 伪AR·相机叠加 | 无 WebXR 但有相机（iOS Safari/PWA） | getUserMedia 相机背景 + 照片叠加（诚实标注"伪AR"） |
| `preview` 3D·预览 | 桌面 / 无相机 / 非安全上下文 | 渐变背景 + 拖动环视（demo 视频录制路径） |

能力检测 `capability.ts`：纯函数 `decideArMode(flags)`（可测）+ 采集器 `detectArCapability()`。
文案按缺什么说什么（iOS 无 WebXR / 需 HTTPS / 无相机），不做死按钮。

## 3. 两种布局（v1）

- **单张锚定**：一张照片一个相框，放在 hit-test 命中点。
- **环绕个展**（XOSMO 效果的轻量版）：N 张照片按黄金角螺旋绕垂直轴排布
  （高度 0.95–2.05m，半径 0.85–1.25m，朝向中心，确定性 seed——同一锚点每次重现同一布局）。

## 5. 诚实边界（对外口径也按这个说）

- **不承诺**"关掉 app 一个月后原位厘米级重现"：ARCore Cloud Anchors 无 Web 通道，
  WebXR persistent anchors 支持面窄。
- v1 语义：现场放置 + 本次会话稳定跟踪 + GPS 存"大概位置"；重访 = `nearby.ts` 邻近判定
  （≤150m）→ "你在照片附近，举起手机" → 重新贴合放置。
- 后续深化方向（文档/视频里说"后面再深化"）：WebXR anchors 持久化（Chrome 实验特性）、
  iOS USDZ Quick Look 通道、视觉锚点（Augmented Images 类）。

## 6. 交互流（suggest-then-confirm）

```
选照片（相册多选 → readExif 拿 GPS；或从地球取已钉照片）
→ 选布局（单张 / 环绕个展）
→ 进入 AR（能力分流三模式）
→ 放置（hit-test 点地面/桌面；伪AR/预览点按钮）
→ 退出 → 确认面板："钉回地球？"（GPS 来源：EXIF > 放置时定位 > 无则 needPlace 诚实提示）
→ 确认 → saveAnchor(pe-ar-anchors) + 直写 userMarks + requestMapFocus 飞过去（近场↔远场闭环演出）
→ 锚点列表：重访（定位 → 距离 → 近了才开 AR 重贴合）/ 去地球看 / 删除（连带撤钉）
```

可观测：`startAgentRun('重返现场 · …')` + phase（能力检测/选照片/进入AR/放置/钉回地球）+ 内联 RunTrace。

4. iOS：伪 AR 相机叠加（诚实标注）；桌面：3D 预览（demo 可录）

## 8. 实现结果与踩坑记录（2026-07-05 落地）

已全部落地并过门禁（build 净 / vitest 560 全绿 / AR 代码零进首屏 chunk / preview E2E 两轮）。
30-agent 对抗审查确认 13 个问题已全修，其中三个值得记住的坑：

1. **`local-floor` 参考空间**：three 的 WebXRManager 默认申请 `local-floor`，但 immersive-ar
   默认特性集只有 viewer/local——不 `renderer.xr.setReferenceSpaceType('local')` 真机会直接
   NotSupportedError 进不了 AR（ARButton.js 官方模式同此）。hit-test 给真实平面位姿，放置高度不受影响。
2. **dom-overlay 的 `beforexrselect`**：AR 会话里点 HUD 按钮默认同时派发 XR select——不在 overlay
   根上 `beforexrselect → preventDefault()`，点退出键会顺手误放置一张照片。
3. **suggest-then-confirm 的快照纪律**：确认面板落库必须用「进 AR 那一刻」的照片快照，
   不能读实时 state——否则选照片的异步窗口里换了批次，用户确认的和落库的会分叉。

真机验收状态：WebXR 路径按标准 API 实现 + 桌面三模式 E2E 已验，**安卓 Chrome 真机未验**
（验过才能说"能用"）；伪 AR 相机流沿用诗歌树加固版三坑修复。

### 8.1 第二轮迭代增补（迭代四~六，同日）

- **双向闭环**：地球照片详情卡（AR 锚点钉）→「⚓ AR 重访」深链（带 `&anchor=<id>`、合并现有
  query 旗标不剥 ?rec/?embed）→ 运行页对应锚点高亮+滚入视口。近场→远场→近场全闭环。
- **放置体验**：WebXR 放置后圆环持续跟踪，点其他位置可挪动（pose 上报与状态迁移解耦，
  落库的是最终位姿）；预览模式放置后停自转（落定感）；重访时按钮文案"重新贴合到这里"。
- **鲁棒性**（第二轮对抗复审 9 个确认全修）：mode 进会话快照不随 cap 解析翻转、
  aliveRef 挡卸载后的悬挂 run、确认蒙层与按钮禁用口径一致（不许假取消）、
  定位硬超时（权限弹窗晾置不锁死页面）、相机拒权文案不被就绪文案覆盖、照片数量口径如实。
- 触点补记：MyMapTab 共两处一行改动（resolveDetail photo 分支 + 拍立得 DOM 贴点击）透传 arAnchorId。
