# GMI 贡献去重验收

比赛讲解里允许同一件展品同时保留端侧 OCR 和 GMI 云视觉证据，但钉地球元数据里的 `gmiContributions` 必须按链路阶段计数，而不是按标签条数计数。

本轮新增 contract 覆盖：

- 端侧 OCR 先读展签，GMI 再补充中英文展签文本时，`labelOcrEngines` 保留 `local-vision` 与 `gmi-vision` 两类证据。
- 多条 `gmi-vision` 标签只点亮一次 `vision` 贡献，避免比赛卡片把重复 mock 标签说成多个 GMI 能力。
- 未生成 3D 时仍只展示 `视觉识别 · 结构化补全 · 导览/时间线`，不伪造 `3D兜底`。
- KIRI / GMI 3D 仍在 `reconstructing` 时，即使已有 mock `splatId` 和 `taskId`，也只保留任务状态，不提前点亮 `3D兜底`。
- GMI 3D 已 `ready` 但包装层带空格或大小写差异时，归一后仍点亮 `3D兜底`，避免展品卡可看而比赛贡献漏计。
- 观展史时间线也复用同一 3D 可渲染判定，`failed` / `reconstructing` 残留任务 id 不再显示 3D 标记。

对应测试：`src/app/lib/exhibition/competition-demo-contract.test.ts` 的“端侧OCR和多次GMI展签识别并存时贡献只按链路阶段去重”、“KIRI 3D 生成中即使已有任务id也不提前计入GMI 3D兜底”与“GMI 3D ready 状态带包装空格和大小写时仍计入3D兜底”；`src/app/components/VisitTimeline.test.ts` 的“GMI/KIRI 3D 未就绪但残留任务 id 时不误亮 3D 标记”。
