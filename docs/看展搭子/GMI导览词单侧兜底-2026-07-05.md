# GMI 导览词单侧兜底验证

本轮补强看展搭子链路里的一个半成功场景：KIRI 生成 3D 后，GMI 可能只返回一句私人导览词，或只返回时间线位置。展品卡不能因为少一个字段就退成空白。

## 演示价值

- 真实云模型输出不一定严格成对返回 `curatorNote` 和 `timelineNote`。
- 只要 GMI 至少给出一个可展示字段，就保留 `source: gmi`，同时用本地兜底补齐另一侧。
- 这让“3D 展品卡 → 私人导览词 → 时间线位置 → 钉回地球/展馆详情可展示”的闭环更稳定，不消耗真实 GMI 或 KIRI API。

## 本地验证

- 新增 `src/app/lib/exhibition/curator.partial.test.ts`。
- 用 mock 覆盖 `guideCard.oneLineGuide` 单独返回和 `modelCard.timelineSummary` 单独返回两种情况。
- 补充 mock 覆盖 GMI 把 `guideCard` 与 `modelCard` 拆成数组项返回时，导览词和时间线仍能合并成同一张 3D 展品卡。
- 补充 mock 覆盖 GMI SDK 风格的单个 `toolCall.functionCall.args` JSON 字符串包装，避免函数调用壳导致导览词/时间线丢失。
- 补充 mock 覆盖 GMI SDK 风格的 `functionCall.parameters` 对象和 `functionCall.params` JSON 字符串包装，避免不同工具调用参数名导致 KIRI 后的 3D 展品卡退回本地导览。
- 补充 mock 覆盖 GMI 把 3D 展品卡字段放进 `message.content` 的 `output_json` / `json_object` 内容块，避免只识别到内容块类型而丢失导览词和时间线。
- 补充 mock 覆盖 GMI 把导览词放在 `message.content`、把时间线位置放在 `tool_calls.function.arguments` 的混合返回，避免只读取内容块导致 3D 展品卡时间线退回本地兜底。
- 验证单侧 GMI 字段被保留，缺失字段由本地导览或本地时间线补齐。
