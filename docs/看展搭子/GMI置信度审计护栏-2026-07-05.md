# GMI 置信度审计护栏

本轮补强看展搭子链路里的末端审计字段：GMI 结构化补全返回的置信度最终必须以 `0-1` 数值进入草稿卡、钉地球详情和时间线。

## 演示价值

- 真实 SDK 或旧缓存可能把置信度漏成 `92`、`8.7` 这类百分制 / 十分制数值。
- `applyCritic` 现在会在草稿完成前把这些值归一成 `0.92`、`0.87`，让展品卡继续展示可信的 `GMI·92%` 审计信息。
- 无法解释的脏值会被清空，并写入审计理由，不会把 `NaN` 或超范围值钉回地球。

## 本地验证

- `src/app/lib/exhibition/critic.test.ts` 使用本地 mock draft 覆盖百分制、十分制和非法置信度。
- 不调用真实 GMI 或 KIRI API。

## 2026-07-05 分数式 / 对象化兜底

- 旧缓存或真实 SDK 若把 GMI 置信度留成 `92/100`、`confidence score: 8.5/10` 或 `{ value: 8.4, max: 10 }`，`applyCritic` 会在草稿完成前继续归一成 `0.92`、`0.85`、`0.84`。
- 这保证展品卡、钉地球详情和时间线看到的是同一套 `GMI·xx%` 审计口径；不可解释的脏值仍会被清空。
- 验证用例继续只使用本地 mock draft，不调用真实 GMI 或 KIRI API。

## 2026-07-05 置信度别名字段兜底

- 真实 SDK 或中间缓存若把置信度命名成 `confidence_value`、`normalizedConfidence`、`gmiConfidence` 或 `estimatedConfidence`，结构化补全阶段和末端 `applyCritic` 都会继续归一到 `0-1` 数值。
- 这让演示里的草稿卡、钉地球详情和时间线继续展示同一套 `GMI·xx%`，避免字段名变化让审计信息消失。
- 新增验证仍只使用本地 mock，不调用真实 GMI 或 KIRI API。
